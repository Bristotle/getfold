# Fold, working conventions

## Writing copy

**Never use em dashes or en dashes.** Not in user-facing copy, not in code
comments, not in commit messages, not in documentation. This includes the
HTML entities `&mdash;` and `&ndash;`.

Rewrite the sentence instead of substituting a character. A dash is almost
always doing one of these jobs, and each has a better replacement:

| Instead of | Write |
| --- | --- |
| A dash joining two complete thoughts | Two sentences, or a comma |
| A dash introducing an explanation | A colon |
| A dash around a parenthetical | Commas, or brackets |
| A dash before a contrasting clause | A comma plus `but` or `though` |

For an empty value in a table cell, use a plain hyphen, not a dash.

Check before committing:

```bash
# AGENTS.md is regenerated by `next dev`, so it is excluded.
grep -rn $'[\u2013\u2014]' src/ CLAUDE.md README.md prisma/ supabase/
```

Other copy rules that matter here:

- Write from the reader's side. A church secretary manages *members*, not
  *records*; she sends a *text*, not a *notification payload*.
- Errors say what went wrong and what to do about it. No apologies.
- Numbers, amounts and phone numbers use `.font-numeric`.
- Ghanaian English, Ghanaian examples. `GHS 250.50`, `0244 000 000`,
  Methodist society and circuit, Akwaaba.

## The security boundary

Row-level security in Postgres is what stops one church seeing another's
data. The interface is a mirror of those rules, never the enforcement.

- Runtime reads and writes go through `supabase-js`, so RLS applies.
- Prisma is for migrations and admin scripts only. It connects with full
  privileges and bypasses RLS entirely. Never use it to serve a request.
- The service role key does the same. It exists for the Paystack webhook,
  which has no user session, and nothing else.
- Every capability in `src/lib/permissions.ts` must have a matching RLS
  policy. Adding one without the other promises a restriction the database
  will ignore.

## Things that have already bitten us

- `id` and `updated_at` need database defaults. Prisma generates those
  client side, but this app writes through PostgREST, which cannot.
- Ids are `uuid`, not `text`, so they compare against `auth.uid()`.
- Paystack webhooks are HMAC SHA512 over the **raw** body. Re-serialising
  the parsed JSON changes the bytes and every signature fails.
- Paystack rejects the `.invalid` TLD. Anonymous giving falls back to
  `example.com`.
- Arkesel holds the first message from a new sender name at
  `PENDING APPROVAL`, returning success and deducting a credit while
  nothing arrives. Check with `GET /api/v2/sms/<id>` before debugging code.
- Deleting an organization cascades to its memberships, so the last admin
  guard has to stand down for cascades or an org can never be deleted.

## Testing

There is no test suite. Verification is done by running real flows against
the live services and cleaning up afterwards. Two techniques worth reusing:

- Wrap destructive database checks in a `DO $$ ... RAISE EXCEPTION $$` block
  so the transaction rolls back and leaves no trace.
- Create pre-confirmed users with `supabase.auth.admin.createUser({
  email_confirm: true })` rather than toggling the project's email
  confirmation setting.

Never sign up test users at a real mail domain with invented addresses. The
bounces count against the project and Supabase will restrict sending.
